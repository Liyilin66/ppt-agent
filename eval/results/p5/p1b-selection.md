# P5 · P1-B 关键页多候选 + PowerPoint 择优（接入流水线）

## 做法（`htmldeck/selection.py`，`design_deck(..., judge=)`，请求开关 `key_page_selection`）
- 关键页：约 20% 的内容页，优先章节首页、以图表/原图/比例图/海报为主的页、有焦点数字的页；已签收页不动。
- 候选：现有版本 + 一个换形式的版本（避开相邻页已用的形式，焦点左右对调、主视觉加宽）。阶段 C 里赢得最多的是这类候选，单写艺术指导的不稳定，所以默认不加。
- 评审：两个版本渲染进同一个 PPTX，用 PowerPoint 导出后按页栅格化，独立审稿模型盲评 3 次；默认保留原版，候选领先 ≥0.4 分且多数次被选为最好才替换；有否决项不替换。
- 整套协调：替换后如果和任何一页的轮廓或构图变得相近，撤回。
- 评审标准加一条："同一个数字在标题、大字和说明里重复出现、没有带来新信息，要扣分"。
- 可重复：择优在整套版面复查里进行，结论和复查一起缓存；页面没变就沿用，续跑不再调模型。
- 没有 PowerPoint 的机器上跳过择优并在日志里说明，不用浏览器预览代替。

## 集成测试（CNNIC 冻结快照副本，重跑整套复查 + 择优）
| 项 | 结果 |
|---|---|
| 选出的关键页 | 7（3、4、10、15、20、25、33） |
| 没有候选 | 3（10、15、33：除相邻页已用的形式外没有别的形式可选） |
| 候选没通过版面检查 | 1（25：大数字贴着日期） |
| 评审比较 | 3 页：换上 1（第 3 页，4.00 → 4.52，3 次都选候选），保留 2（第 4 页只领先 0.09；第 20 页原版更好 4.67 vs 3.86） |
| 跨页构图冲突撤回 | 0 |
| 写作模型费用 | $0.18（12 次调用；评审另计约 9 次） |
| 续跑 | 0 次模型调用，PPTX 结构哈希与择优后一致 |

## 人工校准
第 3 页换上的版本：结论线和账本让信息更清楚，但中间留了一大块空，而且"17179万人"在导语和账本里各出现一次，评审没有扣分；
原版的巨型数字更有冲击力。两者各有优劣，换上不算错，但不是明显更好。现有的同页重复检查只看大字和账本里的数字，正文导语里的重复检查不到。
