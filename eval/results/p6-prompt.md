# P6 任务（ChatGPT 对 P5 报告的回复，2026-11-19，摘要）

判断：P5 方向正确；瓶颈是"资料 → 内容策划 → 视觉素材匹配 → 页面设计"整条链路，而不是再加图表规则或候选数量。
最严重的是全新生成的内容波动（16 → 11 内容页、数据序列 2 → 0）；其次是 63 张候选图只上 1 张（发现 ≠ 分类 ≠ 匹配；先写窄论点再找图；旧版面计划不给原图留位置）。

## P0 内容规划稳定化
- Evidence Inventory：主题/子主题、关键事实与来源、指标/对象/时间/单位、可比序列、原文图候选、可支持论点、证据关系；稳定 ID，可复用核实缓存。
- Coverage Plan / Coverage Matrix：topic_id / claim_id / evidence_ids / available_visuals / importance / assigned_slide_id / uncovered_reason；先做全局覆盖检查再写单页。
- 丢页诊断：gevo3 vs gevo4，哪些主题消失、哪些证据未分配、哪些页因验证删掉、哪些序列被忽略、章节预算失衡、截断/上下文/缓存；区分"证据不足的正常删页"和"波动造成的意外丢页"，后者阻止进入设计。
- 验收：同一冻结证据清单下独立跑 3 次大纲与策划，核心主题与高优先级证据覆盖建议 ≥90%；不要求文案或页数相同，不得固定页数或复制旧大纲。

## P1-A 图形分类与内容匹配前移
- 分类：DATA_CHART / DATA_TABLE / STRUCTURE_DIAGRAM / PROCESS_DIAGRAM / ILLUSTRATION / UNKNOWN；gevo4 第 8 张彩色表头表格不能再走普通原图通道并被缩小。
- Figure–Claim Matching：每张图记录类型、来源页与图注、主题、指标与时间、可支持 claim_ids、建议展示形式、最低可读尺寸、许可、核验状态；策划阶段就让模型看到；允许"原图主导"的页面（论点可以更宽但不能编造）。
- 版式缓存滞后：主要视觉素材变化时只失效该页的 visual brief 与布局缓存。
- 验收：表格不误判；匹配有理由；能主动策划原图主导页；原图可读；不匹配有拒绝原因；冻结的 20～25 页内容里至少 3 种原图/图表表达；原图引用与原生可编辑分开统计。

## P1-B Visual-first 设计
- 构图策略（不是模板）：通栏图表主导、图表 + 编辑式解读、多指标对比、图解主导、数据叙事、文字主导；不能把原图塞进文字格子或缩得很小。
- 生成后检查整套节奏：大数字页过密、左右双栏反复、图表总在同一位置、高密度页、强视觉页、相邻页相近。

## P2 多候选优化
- 先分析 IEA 0/6 失败原因（无可选构图、没有实质差异、几何失败、事实/图表失败、审美不如、领先不足、相邻冲突、误判）。
- 候选必须在主要视觉组织上明显不同（图表成为主视觉、大数字与图表整合、新阅读路径与比例）；只换左右或颜色不算；没有合理替代就跳过。
- 12 页固定集（中英文、图表、原图、纯文字）对比原路线与新路线：候选成功率、有实质差异比例、PowerPoint 通过率、胜出比例、人工判断、每页费用、整套构图变化。

## P3 30～50 页连续生成验证，无重大阻断再进 100 页。
