# 同一需求：ppt-agent、Claude Code、Codex（2026-11-10）

需求：根据信通院《人工智能发展报告（2024年）》（64 页）做 20 页管理层汇报，重点讲企业应用机会和治理风险，咨询风格。每个工具各生成一次。

| 页面上的数字 | 21 | 43 | 97 | 9 |

| 原生图表 / 表格 | 0 / 0 | 3 / 2 | 2 / 3 | 0 / 3 |

项目作者的排序：Claude Code > ppt-agent 升级后 > Codex。排序时看的是样式微调之前的版本（整页深色观点页、图表高亮、表格深色表头都是排序后加的），之后没有重新排序。

**这不是盲评，也不能说明 ppt-agent 比 Codex 好。** 文件虽然随机改名，作者一眼认出了来源，而且是自己的项目；样本只有一个需求、各一次。

## 怎么读这些数字

- 「能找到」用脚本判断：数字字面出现在 PDF 文本里。不代表指标配对正确。
- 对 Claude Code 那份抽查了 14 处，13 处和报告一致；另一处「标识办法已于 2025 年 9 月施行」超出报告（报告里只有征求意见稿），本身未必错。没找到的 8 个数字多是自算倍数或行动计划。所以**直接用大模型做，也不一定会编数字**，这次看不出 ppt-agent 在准确性上有优势。
- ppt-agent 的区别在于：按页给出处，并在生成时做规则核对。它的内容密度和论证仍明显低于 Claude Code。
